# kn-recovery

Восстановление KeeneticOS по TFTP из командной строки Linux.

Свободная замена Windows-утилите `krutil_en.exe` («Keenetic Operating System
Recovery»), которая идёт в комплекте с recovery-прошивкой. Ничего не пишет в
роутер сама: роутер в режиме восстановления сам забирает файл прошивки с
TFTP-сервера, который поднимает эта программа.

Одна зависимость — Python 3.8+. Больше ничего ставить не нужно.

## Зачем

Windows-утилита требует Windows и графический интерфейс. `kn-recovery`
работает в Linux, запускается из скрипта, умеет **проверить, что роутер
действительно вышел на связь**, не передавая при этом ни байта, и проверяет
целостность прошивки до начала работы.

## Установка

```sh
git clone https://github.com/MrCripe/kn-recovery.git
cd kn-recovery
chmod +x kn-recovery
```

## Использование

```sh
# 1. Посмотреть, что внутри прошивки (root не нужен)
./kn-recovery info KN-1221_recovery.bin

# 2. Убедиться, что роутер виден (ничего не записывается)
sudo ./kn-recovery detect KN-1221_recovery.bin

# 3. Восстановить
sudo ./kn-recovery flash KN-1221_recovery.bin
```

Короткая форма тоже работает:

```sh
sudo ./kn-recovery KN-1221_recovery.bin
```

### Команды

| Команда | Что делает |
|---|---|
| `info <прошивка>` | разбирает образ: модель, версия, CRC32. Root не нужен |
| `detect [прошивка]` | ждёт запрос роутера и докладывает, **файл не передаёт** |
| `flash <прошивка>` | ждёт запрос и отдаёт прошивку |

### Полезные флаги

| Флаг | Смысл |
|---|---|
| `-i`, `--interface` | сетевой интерфейс (по умолчанию выбирается сам) |
| `--set-ip` | добавить `192.168.1.2/24` и снять адрес после работы |
| `-w`, `--wait` | ждать запрос не дольше N секунд (0 — бесконечно) |
| `-y`, `--yes` | не спрашивать подтверждение |
| `-p`, `--port` | порт TFTP, по умолчанию 69 |
| `--timeout`, `--retries` | таймаут и число повторов на блок |
| `--blksize` | размер блока TFTP, по умолчанию 512 |
| `--expect-peer` | ожидаемый адрес роутера, по умолчанию `192.168.1.1` |

## Как проходит восстановление

1. Отключите от роутера все кабели и выключите питание.
2. Соедините компьютер с роутером Ethernet-кабелем (любой порт LAN).
3. Зажмите кнопку **Reset** и, удерживая её, подайте питание.
4. Отпустите **Reset**, когда индикатор **Status** начнёт мигать.
5. Запустите `kn-recovery flash ...` — роутер сам попросит файл.
6. Дождитесь окончания записи и не выключайте питание.

Порт, к которому подключён кабель провайдера, лучше не использовать.

## Как работает определение роутера

Отдельного «опроса» роутера не существует: загрузчик Keenetic в режиме
восстановления сам присылает TFTP-запрос на адрес `192.168.1.2:69`. Поэтому
обнаружение — это факт прихода запроса, и он подтверждается четырьмя шагами:

1. **Линк на интерфейсе** — есть ли физическое соединение.
2. **Адрес `192.168.1.2/24`** — загрузчик ищет сервер именно там.
3. **ARP-проверка `192.168.1.1`** — предварительная оценка, может быть и
   другое устройство.
4. **TFTP-запрос** — окончательное доказательство. Программа печатает адрес
   источника, запрошенное имя файла, режим и опции клиента, а также сверяет
   имя с моделью в прошивке.

Именно поэтому `detect` — безопасный способ убедиться, что всё настроено:
он показывает факт обнаружения и ничего не передаёт.

## Проверка прошивки

До начала работы программа проверяет образ и отказывается работать с битым
файлом:

* размер не меньше 1 МиБ;
* подпись `ZNBG` в 60-байтовом трейлере в конце файла;
* CRC32 тела образа (`~zlib.crc32`) совпадает с записанной в трейлере;
* имя модели читается из трейлера.

Подробный разбор формата — в [PROTOCOL.md](PROTOCOL.md).

## Тесты

Роутер не нужен: TFTP-обмен проверяется по loopback.

```sh
python3 tests/test_kn_recovery.py
```

## Ограничения

* TFTP-сервер работает только на чтение: запрос на запись (`WRQ`)
  отклоняется.
* Проверка CRC подтверждает целостность файла, но не то, что прошивка
  предназначена именно вашей модели. Сверяйте модель из `info` с моделью
  роутера.
* Реализация написана по разбору `krutil_en.exe` и проверена на прошивке
  KN-1221. На других моделях Keenetic протокол восстановления тот же, но
  на живом устройстве это не проверялось.
